## Notes

- **Why US-035 was listed before US-032.** US-032 depended on US-030, which wasn't done, so it was under **Refine next**, not **Next up**. US-035 had all its dependencies done. It also still has no Files to touch, Out of scope or Tests to add, so it's still unscoped.
- **Found while checking against the code, and where each went:**
  - **A latent `400` from the model API.** `lastMessages` takes the last 6 messages. A chat that alternates and ends on a question gives a window that starts on an answer, and the Messages API requires the first message to be `user`. From the fourth question on, every request would fail as `upstream`, and a fake provider can't show it. Fixed in US-031 (D-050); US-029's `lastMessages` test is updated there.
  - **Nothing could be a follow-up.** `commands.json` has no question text and no `related` field, and the payload is a list of questions. US-030 adds an optional `question` (D-046).
  - **A rate limiter on a serverless host.** Counts in memory aren't shared or durable. A real store needs an account and a package the spec doesn't name, so it is D-045 for Caleb, with in-memory as the default.
  - **`textarea` and `role="combobox"`.** F4.5's newline needs a textarea and F3.4 needs the combobox role. Axe reports only a minor finding for the pair (checked directly), so it can be built (US-032 Notes).
  - **A client-side constants file.** The 500-character limit has to reach the page without dragging the SDK in. US-031 creates `lib/chat-limits.ts` for it.
  - **A thread that can't hold free text.** History state held command names only, so a chip click after a question would lose the question on Back. D-053 puts exchanges in the same array.
  - **Streaming and a screen reader.** An `aria-live` region around a streaming answer reads half-sentences. US-032 keeps the in-flight text out of it.
- **Why US-032 was split.** It was 5 points with ten criteria, and it held a new input element, a new turn model, streaming and announce-once, a layout change and "New chat". The layout half (F4.5's pinned input and growth, F4.6, F4.9's counter) is US-081, 3 points, after US-032. F4.5's keys and F4.9's 500-character stop stay in US-032, so no step ships a control that doesn't work.
- **Order.** US-030 → US-031 → US-032 → US-081 → US-033. US-031 depends on US-030 (both change `lib/chat.ts`, and its log needs the cited count). US-032 depends on US-031 so the client is built against the statuses the route really sends. The board checks the shared files.
- **Not verified, and why.** There is no API key on this machine, so the `400` for a window that starts on an `assistant` message is the documented rule, not something tried. Axe was run through `axe-core`, which is in `node_modules`; `@axe-core/playwright` isn't installed until US-035.
